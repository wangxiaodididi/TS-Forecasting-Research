# GTR 拆解、局限诊断与修改手册

## 0. 修改顺序

必须先让官方 GTR 在 ETTm1 H=96 上以原超参跑通，并且建立真实基线，再继续改造。只改一个模块、一个假设，禁止模型和训练参数同时大幅改变。

## 1. 官方核心（不改）

`vendor/GTR/models/GTR.py`：

- 可学习全局周期矩阵 `Q`，维度 `[cycle, enc_in]`；
- `gather_index`：依据当前 `cycle_index` 与历史时间位置提取全局周期表示；
- `GTR.linear()` 全局检索映射；
- `GTR.conv2d()`：把局部历史与检索表示融合；
- 加性残差 `x_input + global_information`；
- 主干 `input_proj → MLP → output_proj`，外层 RevIN。

原始编码最重要的是周期检索 Q + 对齐 2D 融合，其他部分后续可单独测量，但不在第一轮修改。

## 2. 修改模块与输入/输出

`extensions/models/GTRSignalCore.py` 调用 `self.base = GTR.Model(configs)`，保持原模型方法不动；对历史窗口做一层 Haar 变换（先归一化，仅使用过去），得到低频和高频的可解释系数，各用 `Linear(ceil(T/2), H)` 映射；修正项最后乘回原始窗口 std 再加到原 GTR 输出。初始线性头全 0，确保新模型初始输出和原 GTR 完全一致。

四种变体：

- `GTRLinearResidual`: 普通线性残差，控制新增参数收益；
- `GTRHaarLow`: 只预测低频修正；
- `GTRHaarHigh`: 只预测高频修正；
- `GTRHaarDual`: 两路均开启。

注意：Haar 高频不保证一定可预测；低频也不等同纯经济趋势。`high_energy_ratio` 仅为描述指标，不是注意力权重或因果归因。

## 3. 先分析，再设计

1. 在 **validation** 上观察 `GTR` 的误差是否随高频能量增大而增加；原模型在稳定周期和突变窗口中的表现是否不同。
2. 先比较 `GTR` vs `GTRLinearResidual`。若已明显改善，说明新增预测容量可能是主要因素。
3. 再比较 `GTRHaarHigh` 与 `GTRLinearResidual`，验证小波局部细节是否真正提供增益。
4. 最后比较 `GTRHaarLow` 与 `GTRHaarDual`，判断低频/高频共同使用是否必要。
5. 仅在 validation 选好结构和参数后固定 test；不得使用测试曲线反复筛选方案。

## 4. 进一步的检查

- **收敛**：train vs val loss 是否同时降低、最佳验证 Epoch、过拟合差距；
- **优化**：可选梯度 L2、Q 矩阵与头部参数更新比例（下一阶段通过 hooks 加入，不改 Adam）；
- **表征**：可用官方 Q 的周期位置热力图判断学习到的周期是否稳定，避免把图像当作预测能力证明；
- **模块贡献**：使用 `python -m lab.explain RUN_ID --split val` 导出每步 GTR 预测和修正量；
- **公平性**：相同 split/horizon/seed/batch/epochs/learning_rate/lradj/优化器，比对参数量和耗时；
- **统计检验**：优先逐预测时点配对误差和滚动段稳定性，避免只按一个随机种子得出确定结论。

## 5. 增加一个新模型的固定修改位置

1. 复制 `extensions/models/GTRHaarHigh.py`，命名 `GTRMyModule.py`；
2. 创建 `configs/experiments/my_module.yaml`；
3. 在 `lab/config.py` 的 `MODEL_FILES` 注册名字及配置；
4. 在 `lab/extend.py` 的 `MODELS` 注册它；
5. 给 `tests/` 增加前向 shape、backward、初始一致性测试；
6. 小样本通过后才跑完整数据。

除非明确决定改论文核心，否则禁止改 `vendor/GTR/models/GTR.py`。

## 6. 数据-模型适配诊断

可以先运行：

```bash
./.venv/bin/python -m extensions.diagnostics.data_signal_audit --dataset ETTm1
```

本工具只读取训练段，输出每个变量的周期滞后相关、Haar 高频能量比，以及汇总 JSON。它不是预测效果检验，不能用来直接证明信号模块有效。对未来窗口的解释和条件性能，应当使用固定的 validation 记录与逐步预测贡献 CSV，且不能看 test 后反复改参数。
